# S2A and S2A2

[S2A2](https://github.com/luciangreen/S2A2) is a second Spec to Algorithm. This page compares the `s2a/4` in mnns with S2A2's input/output synthesis, `io_synth`, and describes the bridge that lets mnns call S2A2: [`prolog/s2a/s2a2_bridge.pl`](../prolog/s2a/s2a2_bridge.pl).

## The comparison (13 November 2026)

This was S2A2's state before the work under "Status now".

**Will S2A2 use the genetic algorithm?** Only as a last resort, and only when turning input/output examples into a program (`io_synth`). It runs when none of the direct methods fits (a single expression, map, filter, template or foldr). That is on by default and can be turned off with `ga(false)`. For example, "sum of squares of the evens" needs it, because no single direct method splits it into parts. On the 12 comparison tasks it was tried only for projection and cubic, and it found nothing for either. The optimisation stage (`s2a2.pl`, `fold.pl`) never uses it, and the mnns `s2a/4` has no genetic algorithm. It only chains together a fixed set of building blocks, so it doesn't let S2A2 find new kinds of algorithm.

**mnns `s2a/4` compared with S2A2:**

| | mnns `s2a/4` | S2A2 `io_synth` |
|---|---|---|
| Tasks solved (of 12) | 4: extracting part of a compound term, and linear, quadratic and cubic formulas | 10: everything with lists or recursion, plus linear and quadratic |
| Held-out inputs | all its programs pass | all its programs pass |
| Proof | none: it only confirms the training examples are reproduced (an empty proof) | proved equal to a reference program for every input of the declared types |
| After learning | feeds the mnns pipeline | `fold.pl` derives faster versions |

They complement each other. mnns has two small, exact methods S2A2 lacked: taking part of a compound term (`box(_, A) → A`) and solving polynomials of degree up to 3 exactly. S2A2 covers the recursive list programs that mnns's own requirement R4.1.2 asks for but doesn't yet meet.

**Two S2A2 bugs found by the comparison, both fixed and tested:**

- **Name clash:** a task named `reverse` produced `reverse(A,B) :- reverse(A,B)`, which calls itself instead of the library. Library calls are now written as `lists:reverse/2` when the names clash.
- **Hang:** the genetic algorithm looped forever when the input was a compound term like `box(...)`, because none of its building blocks accept that input type. It now gives up at once, and its programs are checked on every example before being returned.

The suggested next step was an adapter so mnns calls S2A2, plus adding mnns's projection and polynomial solving to `io_synth`. That would cover all 12 tasks.

## Status now

Both have been done.

**S2A2 has mnns's two methods** ([S2A2 pull request #10](https://github.com/luciangreen/S2A2/pull/10)):

- **projection:** a unique address whose subterm equals the output in every example, through the same functors, gives `projection(box(_, A), A)`;
- **polynomial:** degree 1 to 3, solved exactly with integer coefficients and checked on every example, gives `cubic(A, B) :- B is A*A*A+1`.

They are tried after a single expression, so list tasks are solved as before. Both are proved equal to a reference program by S2A2's `io_proof.pl`. On the 12 tasks, run with held-out inputs (S2A2's `docs/compare_mnns_s2a.pl`):

| task | mnns `s2a/4` | S2A2 `io_synth` | held out |
| --- | --- | --- | --- |
| projection | input address | projection | both pass |
| swap_pair | no algorithm | expression (`reverse/2`) | passes |
| affine | affine | expression | both pass |
| quadratic | quadratic | expression | both pass |
| cubic | cubic | polynomial | both pass |
| reverse | no algorithm | expression | passes |
| double_each | no algorithm | map | passes |
| evens | no algorithm | filter | passes |
| sum | no algorithm | expression | passes |
| minmax | no algorithm | template | passes |
| dropmin_each | no algorithm | map, with a filter inside | passes |
| inc_all | no algorithm | map inside map | passes |

mnns `s2a/4` solves 4 of the 12; S2A2 solves all 12.

**mnns can call S2A2.** `mnn_s2a2:s2a2(Name, Spec, Options, Result)` takes the same spec as `s2a/4`:

1. `s2a/4` runs first, without a table, so every case it already solves gives exactly the same program.
2. When it returns `no_algorithm(_)`, S2A2's `io_synth` is asked for a program from the same examples, and the result comes back as an `mnn_program/5` in the mnns IR: one `mnn_pred` per predicate, including invented helpers. Its trace is `s2a2_io_synth(Name, Kind, examples_reproduced(N))`.
3. If S2A2 finds nothing too, `allow_table(true)` still gives `s2a/4`'s table.
4. Problems with the spec itself (empty, conflicting examples, a bad shape, bad options) are reported by `s2a/4` and not sent to S2A2.

With `reference(Clauses, RefName)`, the program also gets an mnns proof that it equals the reference for every input of its types:

```prolog
proof([proof_step(1, induction_equivalence, [], equivalent(domain(types([list(int), any])), modes(all)))])
```

mnns's own checker accepts it: `check_proof(Program, Reference, Proof, accepted)`, where `Reference` (the reference as an `mnn_program`) is in the trace as `s2a2_reference(Reference)`. The checker re-proves the claim with `prolog/proof/induction_equivalence.pl`. That file is a copy of S2A2's prover kept in mnns, so the check does not load or trust S2A2. If no proof is found, the field is `proof([])` and the trace says `s2a2_proof(RefName, not_proved)`.

The bridge finds S2A2 at `$S2A2_HOME`, or in `../S2A2` or `../s2a2` beside this repository. Without it, `s2a2/4` gives `s2a/4`'s results unchanged. `tests/s2a2_bridge_tests.pl` has 8 tests; it is skipped when S2A2 is absent. The CI workflow clones S2A2 beside mnns so they run.

```prolog
?- use_module(prolog/s2a/s2a2_bridge),
   Spec = [ [[input,[['A',[1,2,3]]]],   [output,[['B',[3,2,1]]]]],
            [[input,[['A',[4,5,6,7]]]], [output,[['B',[7,6,5,4]]]]] ],
   mnn_s2a2:s2a2(reverse, Spec, [], P).
P = mnn_program(mnn_s2a2_reverse, meta(s2a2_io_synth(reverse, expression), ...), ...,
                proof([]), trace([s2a2_io_synth(reverse, expression, examples_reproduced(2))])).
```

## Optimisation with S2A2

mnns can also call S2A2's optimisation stage, on `mnn_program`s:

- **`s2a2_learn(Pairs, Options, Algorithm)`** runs S2A2's `learn/2` on `[pair(Before, After, Targets)]`. It learns an algorithm: operators with conditions learned from the pairs.
- **`s2a2_apply(Algorithm, Program, Targets, Options, Result)`** runs S2A2's `apply_algorithm/5`. The trace holds the steps and S2A2's prover's verdict on the targets, over every input built from the input predicates. If the pairs were too few to learn safe conditions, the verdict is `refuted(Input, ...)`. For example, two pairs that also delete the wrapper teach an unconditional `del_clause`, and the prover refutes it on a new program.
- **`s2a2_derive(Spec, Mode, Options, Result)`** runs `fold.pl`'s spec to algorithm and returns a faster program: an accumulator, a tupled or fused program, or a deforested one. It returns one only when `fold.pl`'s `verify/5` finds it total and the specification functional, which makes them equal on every input of `Mode`. The trace holds the strategy, the lemmas, the verdict and a bounded check. Sum gives `sum_acc/3`, and flatten gives `flat2_fuse/3` with no `append`.

## Fixed since the bridge was added

- **S2A2's proofs are in mnns's format.** A program learned from examples, given a reference, carries an `induction_equivalence` proof that mnns's checker re-proves.
- **mnns calls S2A2's optimisation.** `s2a2_learn/3`, `s2a2_apply/5` and `s2a2_derive/4`.
- **The sandbox runner works on SWI-Prolog 10.** `library(error)` there checks types with the built-in `system:is_address/1`, which `library(sandbox)` did not list as safe, so `nth0/3` and `nth1/3` were refused. The runner now declares it safe; it is a pure type test. The whole suite passes on SWI-Prolog 9 (CI) and 10.

## Still open

- **Optimisation proofs are S2A2's, not mnns's.** The results of `s2a2_apply/5` and `s2a2_derive/4` carry S2A2's proof results in their trace, with `proof([])`. mnns does not re-check S2A2's prover verdicts or `fold.pl`'s derivations; that would mean porting S2A2's prover and `fold.pl`'s unfold/fold machinery into mnns's checker.
- **`s2a/4` itself is unchanged.** To use S2A2, call `s2a2/4` instead.
- Neither system finds algorithms from first principles: both build programs from fixed methods. S2A2's [`docs/scope.md`](https://github.com/luciangreen/S2A2/blob/main/docs/scope.md) describes what is hardwired.
